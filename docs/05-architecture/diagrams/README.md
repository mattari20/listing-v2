# Architecture Diagram Conventions

- Use text-based Mermaid diagrams where they clearly express the view.
- Label scope and abstraction level: context, container, component, runtime, data flow or deployment.
- Label important relationships and exchanged information.
- Distinguish confirmed external parties from proposed integrations and research-only sources.
- Never include secrets, production hostnames, credentials or personal information.
- Make Deeni Madaris default-OFF enforcement explicit on every public discovery path that could expose provider categories.
- Show source authorization and human approval boundaries in source-ingestion/publication flows.
- Do not imply a source, connector, vendor, production environment or permission has been approved without evidence.
- Prefer diagrams that answer a stakeholder question; avoid exhaustive class-level diagrams in M2.
