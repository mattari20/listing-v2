# Data Rights and Provenance Standard

## Separate software rights from data rights
An open-source crawler license does not grant rights to copy, store, republish or commercialize data found by that crawler. Review each software license and each data/source permission independently.

## Source review checklist
- Official ownership and authority.
- Website terms and applicable policies.
- Open-data or dataset license and permitted purposes.
- Copyright/database rights and attribution requirements.
- API terms, rate limits and redistribution restrictions.
- Robots/access instructions and technical restrictions.
- Personal data, student/minor information and sensitive fields.
- Retention, deletion and correction obligations.
- Commercial-use and onward-sharing rights.
- Evidence of permission and review date.

## Provenance
Each public factual claim should be traceable to one or more sources and include observed/updated dates and a verification label. Preserve original source values separately from normalized values. Keep an audit history of changes and reviewer decisions.

## Status vocabulary (initial proposal)
- Discovered — candidate found, not verified.
- Source checked — source identity/rights reviewed.
- Extracted — data collected, not yet accepted.
- Corroborated — supported by additional independent evidence.
- Verified — passed defined field-specific verification.
- Disputed — credible conflicting evidence exists.
- Stale — refresh target exceeded.
- Withdrawn — no longer eligible for display.

Final definitions and thresholds require an M1 decision.
